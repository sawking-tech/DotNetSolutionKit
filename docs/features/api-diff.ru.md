# Сравнение API

Генерируется с `--DiffApi`, по умолчанию выключено. Флаг передаётся вместе с `--Solution` и каждому сервису, который генерируется позже.

На каждом пулл-реквесте CI генерирует OpenAPI-документ каждого сервиса дважды: из ветки пулл-реквеста и из
ветки, в которую он мержится (обычно `main`). [oasdiff](https://github.com/oasdiff/oasdiff) сравнивает их.
Отчёт попадает в артефакт прогона, а ломающее изменение валит проверку, если оно не объявлено.

В репозиторий ничего не коммитится: оба документа строятся из кода во время прогона, поэтому нет снимка,
который мог бы устареть.

Ветка пулл-реквеста строга всегда: если её документы не построились, проверка падает.

Для целевой ветки есть исключение, и у него есть цена. Иногда сравнивать не с чем: целевая ветка из
версии старше появления контрактов, или генерация схем в ней сломана. Тогда проверка пишет в лог пометку
с именем сервиса и причиной и проходит - иначе пулл-реквест, который чинит генерацию, не смог бы вмержиться,
заблокированный той самой поломкой, которую чинит. Цена: пока починка не влита, ни один пулл-реквест не
сравнивается, и пометка в логе - единственный знак об этом.

## Сгенерировать документы локально

```bash
bash scripts/generate-api-schemas.sh
```

пишет `src/services/*/*.API/api-schema/<service>.json` для каждого сервиса. Каждый сервис запускается с
`--dump-schema` в режиме только схемы, поэтому база, брокер и секреты не нужны. Как и почему:
[ADR-003](../adr/003-api-schema-generation.md). [API-шлюз](api-gateway.ru.md) скрипт пропускает: шлюз отдаёт
документы сервисов, своего контракта у него нет.

## Объявить ломающее изменение

Рекомендуемый способ сломать API - цикл устаревания: пометить путь устаревшим, выпустить это и удалить
путь в одном из следующих релизов - проверка такому пути не мешает. Объявляют находку в
`.github/api-diff-ignore/<service>.txt` только для того, что цикл не покрывает: например, путь ушёл из
документа, а маршрут продолжает отвечать. По строке на находку, с причиной строкой выше:

```
# The legacy export left the document; the route still answers until 2.0.
1.4.0 GET /api/v1/orders/export
# The status became an enum; every value already sent is in it.
1.4.0 PUT /api/v1/orders/{id}/status request-property-became-enum
```

Поля - версия, метод, путь и, необязательно, id проверки; всё копируется из лога джоба. Метод и путь
принимают `*`. Без id проверки строка покрывает все находки по этому методу и пути.

Строка действует, только пока в `version.json` стоит её версия. После подъёма версии изменение уже есть
в базовой ветке, и строка могла бы только спрятать более позднюю регрессию на том же пути, поэтому она
перестаёт действовать сама.

## Что где работает

| Часть | Где |
|---|---|
| Режим только схемы, `SchemaDump` | `Common.Web/Setup` |
| `SchemaHost.Build` | API-проект каждого сервиса |
| Генерация и нормализация | `scripts/generate-api-schemas.sh`, `scripts/normalise_api_schema.py` |
| Проверка | `.github/workflows/api-diff.yml`, на пулл-реквестах |

Workflow написан для GitHub. На другом CI скрипт запускают с обеих сторон и так же сравнивают файлы через oasdiff.
