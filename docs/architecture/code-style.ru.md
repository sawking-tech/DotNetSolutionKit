# Стиль кода

Правила каждого файла репозитория и то, как они держатся. Почему за стиль отвечают форматтеры и откуда правила:
[ADR-007](../adr/007-code-style.ru.md).

Правила лежат в `.editorconfig` в корне. Он вне `template/`, поэтому пакет и сгенерированное решение его не несут.
Правило лежит в одном из двух слоёв:

- применяется: форматтер исправляет его без человека, и сборка или CI на нём падает (`warning`);
- предлагается: ни один форматтер его не применяет; IDE его показывает (`suggestion`) или оно выключено (`none`), и
  сборка не падает.

Группы `.editorconfig` идут в порядке разделов ниже, от базовых правил к вкусовым, и у каждого правила есть
комментарий. Новое правило желательно ставить в его группу с комментарием; это пожелание, его ничто не проверяет.

## Привести изменение к стилю

```bash
python3 scripts/check-style.py --fix                  # байты каждого отслеживаемого файла
dotnet format tool/DotsKit/DotsKit.csproj             # C# инструмента
dotnet format tool/DotsKit.Tests/DotsKit.Tests.csproj # и его тестов: проект форматирует только себя
```

CI запускает то же без исправления: job `One style` проверяет байты каждого файла, а job dotskit собирает
инструмент с `-warnaserror` и запускает `dotnet format --verify-no-changes`. Шаг формата нужен рядом со сборкой:
сборка на SDK 8 пропускает часть правил, в том числе IDE0130.

## Правила, от базовых к вкусовым

### Байты каждого файла

| Правило | Значение | Почему |
|---|---|---|
| `charset` | `utf-8`; `utf-8-bom` для `.sln` | одна кодировка; Visual Studio пишет файл решения с BOM |
| `end_of_line` | `lf` | `.gitattributes` делает каждый текстовый файл LF при любой выписке, и клон на Windows получает те же байты |
| `insert_final_newline` | `true` | файл заканчивается переводом строки |
| `trim_trailing_whitespace` | `true` | без пробелов и табов в конце строки |
| `indent_style`, `indent_size` | пробелы; 4 в `.cs`, `.csproj`, `.sh`, `.py`, 2 в остальных; табы в `.sln` | размер, который был у большинства файлов каждого вида |

`scripts/check-style.py` держит байты этих правил на каждом файле, который отслеживает git, исходники шаблона тоже:
кодировку, концы строк, перевод строки в конце, отсутствие пробелов в конце строк, BOM и отсутствие таба в отступе
там, где нужны пробелы. Размер отступа он не проверяет; в C# его держит `dotnet format`. Ещё он находит кириллицу в
коде вне тестового проекта: код и комментарии к нему на английском.

### Раскладка C# (IDE0055, применяется)

Фигурные скобки на отдельной строке у каждой конструкции, `else`, `catch` и `finally` с новой строки, одна
инструкция на строку, пробелы по умолчанию. Как инициализатор или коллекция разложены по строкам, решает автор
(`csharp_new_line_before_members_in_object_initializers = false`): при `true` форматтер ставит каждый элемент
многострочной коллекции на отдельную строку, и список аргументов становится нечитаемым.

### using и namespace

| Правило | Значение | Слой | Почему |
|---|---|---|---|
| Порядок using | сначала `System`, затем по имени, без пустых строк между группами | применяется | как сортируют источники Microsoft |
| Место | вне namespace | применяется | C# coding conventions |
| Лишний using (IDE0005) | удаляется | применяется | в сборке работает только с `GenerateDocumentationFile` |
| Namespace (IDE0161) | file-scoped | применяется | его область - файл, видна сразу |
| Namespace и папка (IDE0130) | совпадают | применяется | тип лежит там, где говорит его namespace |

### Пустые строки

Не больше одной пустой строки подряд (IDE2000), без пустой строки между двумя закрывающими скобками (IDE2002), одна
инструкция на строку (IDE2001); всё применяется. Инструкция может идти сразу после блока, без пустой строки (IDE2003
выключено), а `=>` остаётся в конце строки (IDE2006 выключено: иначе он переносится на следующую). Python держит
две пустые строки между определениями верхнего уровня, как просит PEP 8.

### Язык

| Правило | Значение | Слой | Почему |
|---|---|---|---|
| Скобки (IDE0011) | вокруг тела каждого `if`, `else`, `for`, `foreach`, `while`, `using`, `lock` | применяется | область тела видна, а не угадывается по отступу |
| `this.` | не пишется | применяется | C# coding conventions |
| Имена типов | `int`, а не `Int32` | применяется | ключевые слова языка |
| Модификатор доступа | пишется всегда, кроме членов интерфейса | применяется | |
| using-инструкция (IDE0063) | IDE не предлагает форму объявления | выключено | конец using-объявления не виден; ни один форматтер не превращает его обратно, поэтому код сохраняет те, что есть |
| Конструкторы (IDE0290) | первичный или явный, на выбор автора | выключено | перевод 117 первичных конструкторов шаблона дал бы командам настоящие конфликты |

### Имена (IDE1006, предлагаются)

Константы в `PascalCase`; поля `private static readonly` в `PascalCase`, как у StyleCop SA1311 и JetBrains;
остальные приватные поля в `_camelCase`. Ни один форматтер не переименовывает, поэтому правила только предлагаются
и сборку не роняют. Префикс `s_` из кода самой Microsoft не взят: [ADR-007](../adr/007-code-style.ru.md).

### Вкус

| Правило | Значение | Почему |
|---|---|---|
| `var` (IDE0007, IDE0008) | ни то ни другое не требуется | на выбор автора |
| Тело-выражение или блок (IDE0021-IDE0027, IDE0053, IDE0061) | ни то ни другое не требуется | на выбор автора |
| `?:` и все ветки switch (IDE0045, IDE0046, IDE0072) | предлагается | IDE предлагает переписать и оставляет это автору |
| Отброшенный результат (IDE0058) | выключено | `_ =` перед каждым вызовом, который возвращает значение, - шум |
| Выражения коллекций (IDE0300-IDE0306) | предлагается | ни один форматтер их не применяет, а IDE0305 приходит только с SDK 10 |

### Правила качества и документация

Каждое правило анализаторов .NET на уровне `warning` (`dotnet_analyzer_diagnostic.severity`), а `AnalysisLevel`
8.0 держит набор .NET 8 и на более новом SDK. Исключения:

- правила глобализации предлагаются: инструмент читает файлы и вывод git, а не текст для людей;
- CA1863, кэширование составного формата, предлагается: горячего пути у инструмента нет;
- JSON002 выключено: JSON-строка теста - это данные файла, в который она пишется;
- в двух местах правило выключено с причиной в `tool/DotsKit/Suppressions.cs`: CA1822 у ключа `_comment_` из
  ADR-006, который System.Text.Json пишет только как свойство экземпляра, и CA1001 у держателя `SemaphoreSlim`,
  который живёт столько же, сколько процесс.

XML-документация описывает каждый параметр своего члена (CS1573 на уровне `warning`): дока, которая описывает часть
параметров, читается так, будто описывает все.

### JSON

Ключи метаданных JSON-файла, `_comment_<Key>` и `_note`: [ADR-006](../adr/006-json-metadata-key-convention.ru.md).
`scripts/check-json-metadata.py` проверяет их на сгенерированном решении.

### Исходники шаблона

`[template/**.cs]` выключает анализаторы для IDE, которая открывает исходники шаблона: в них `//#if` с нулевой
колонки и имена-заглушки, и ни один проект репозитория их не компилирует. `dotnet format` по ним не запускается;
их байты держит `check-style.py`, а их C# будет проверяться на решениях, которые генерирует CI.

## В плане

Хук pre-commit для байтов и раскладки файлов коммита; четыре построчных шаблона StyleCop о пустых строках у скобки
или XML-доки в `check-style.py`; длина строки: 99 в Python, 120 в YAML и Markdown; `dotnet format` на решениях,
которые генерирует CI. См. [ADR-007](../adr/007-code-style.ru.md), раздел «В плане».
