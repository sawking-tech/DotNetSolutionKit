# Работа с ИИ-агентами

В большинстве задач весомых причин отказываться от ИИ-инструментов нет. С ними или без них за качество
и целесообразность результата отвечать должен исполнитель: переложить эту ответственность на
инструмент не получится, и не стоит.

Архитектуру v1 (август 2025 - февраль 2026, 10 коммитов) автор заложил руками. ИИ-агенты вошли в
работу по мере их развития: начиная с работы над v2 шаблон пишется с агентом на модели Claude Opus.
Атрибуции и соавторства модели нет ни в коммитах, ни в файлах: модель не автор решений проекта. Она
используется утилитарно, как высокоуровневый компилятор и инструмент генерации: решение принимает
автор, модель превращает его в код, автор проверяет результат и отвечает за него. Соавторами не
указывают ни операционную систему, ни компилятор, который генерирует оптимальный код, и модель здесь в
той же роли.

Шаблон может развернуть решение, тоже оптимизированное под работу с ИИ-агентами. Правила и скиллы
написаны так, чтобы агент как можно меньше уходил от поставленной задачи, но они не гарантируют, что
агент напишет всё правильно и не испортит архитектуру. Решения агента не принимайте на веру: что
проверяется формально, проверяйте тестами, остальное - глазами. Работать с шаблоном можно и без
агентов.

## Что получает решение

Сгенерированное решение получает правила для агента и скиллы. Флаг `--Agent` выбирает их формат:

| `--Agent` | Правила | Скиллы | План длинной работы |
|---|---|---|---|
| `claude`, по умолчанию | `CLAUDE.md` | `.claude/skills/` | `.claude/session-context/` |
| `opencode` | `AGENTS.md` | `.opencode/skills/` | `.opencode/session-context/` |
| `none` | - | - | - |

Содержимое в обоих форматах одно, отличаются имена файлов и папок.

В правилах записаны слои решения, где что лежит и чем проверить изменение. Скиллы, по одному на
типовую работу:

| Скилл | Работа |
|---|---|
| `scaffold-service` | новый сервис |
| `add-entity` | сущность или агрегат |
| `add-repository` | репозиторий |
| `add-specification` | условие выборки и поиск |
| `add-domain-event` | доменное событие и его обработчики |
| `add-service-class` | сервис приложения |
| `add-controller` | контроллер |
| `add-tests` | тесты сервиса |
| `ef-migration` | миграция сервиса |
| `pick-pattern` | выбор паттерна до кода |
| `self-review` | проверка своих коммитов |
| `code-review` | разбор чужого pull request |
| `plan-and-iterate` | план длинной работы |

Скиллы - часть решения. Каждый из них автор проекта спроектировал осмысленно, как «DSL-надстройку» для
ИИ-агента. `SKILL.md` описывает допустимые операции над системой и каким должен быть их результат. Скилл
называет инварианты и проблемные места, у неочевидных объясняет причину и на примерах показывает, как
писать код, не нарушая заложенной архитектуры проекта.

## Как этим пользоваться

Агент читает файл правил сам. Скилл зовётся по имени или подхватывается, когда задача совпадает с его
описанием. Скилл ведёт по шагам и ссылается на документацию механизма, поэтому агент делает работу так,
как её описывает этот сайт.

Длинную работу ведите по `plan-and-iterate`: агент держит план в файле и не теряет его между сессиями.
