# Шина сообщений

По умолчанию выключена. `--Messaging` выбирается для каждого сервиса:

| Значение | Что получает сервис |
|---|---|
| `none` | шины нет |
| `outbox` | MassTransit на RabbitMQ с транзакционным outbox в схеме сервиса: сообщение сохраняется вместе с изменением, которое его вызвало, и отправляется после коммита |
| `direct` | MassTransit на RabbitMQ без outbox: сообщение уходит прямо в брокер и теряется, если брокер лежит |

`outbox` выбирают, когда сообщение нельзя потерять и нельзя отправить для откаченного изменения;
`direct` - только там, где потеря сообщения допустима.

## Публикация

Из pre-save обработчика доменного события сообщение попадает в outbox внутри транзакции записи, которая
подняла событие:

```csharp
public sealed class PublishOrderPlaced(IMessageBus bus) : IDomainPreSaveHandler<OrderPlaced>
{
    public Task Handle(OrderPlaced e, CancellationToken ct, object? data = null) =>
        bus.PublishAsync(new OrderPlacedV1 { OrderId = e.OrderId }, ct);
}
```

Событие реализует `IBusEvent`, команда - `IBusCommand`. Контракты, общие для сервисов, лежат в
`Common.Contracts` с версией в имени (`OrderPlacedV1`), поэтому ломающее изменение - это новый тип рядом
со старым.

## Потребление

Консьюмеры живут в инфраструктуре сервиса и находятся сканированием. Очереди называются по сервису
(`orders`, `sales_orders`), поэтому два сервиса, потребляющие одно событие, получают каждый свою копию.

## Что идёт вместе с сообщением

Пользователь, который вызвал сообщение, трейс (`traceparent`) и
[идентификатор корреляции](../architecture/web-layer.ru.md#корреляция) пишутся в его заголовки и
восстанавливаются для консьюмера. Поэтому то, что пишет консьюмер, приписывается этому пользователю, а
строки его лога находятся по идентификатору запроса, который их вызвал. Outbox сохраняет заголовки:
сообщение, доставленное из него позже, всё равно их несёт.
Доменные события, поднятые в консьюмере, диспатчатся как в запросе.

## Конфигурация

```json
"RabbitMq": { "Enabled": true }
```

У хоста, учётных данных и повторов есть значения по умолчанию (`localhost`, `guest`, 3 повтора); реальные
учётные данные передаются как `RabbitMq__UserName` и `RabbitMq__Password`. `Enabled: false` регистрирует
шину, которая ничего не делает, и при старте пишет в лог строку уровня critical. С шиной `/ready`
проверяет брокер.

С outbox `GET /api/v1/diagnostics/outbox-stats` показывает, сколько сообщений ждёт и сколько отправлено,
и последние из них; `?filter=` ищет по телу сообщения, например по id заказа. Эндпоинт есть везде, кроме
Production.

Регистрация, контракты, публикация, outbox и консьюмеры подробно:
[Messaging/README.md](../../template/src/common/NamespaceRoot.ProductName.Common.Infrastructure/Messaging/README.md).
