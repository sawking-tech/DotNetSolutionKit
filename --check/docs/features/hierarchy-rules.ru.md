# Правила доступа в дереве тенантов

Генерируются с `--HierarchyRules`, по умолчанию выключены. Флаг передаётся с `--Solution`.

Для продукта, где тенанты образуют дерево (у тенанта есть дочерние тенанты, у них свои), шаблон
добавляет правила, которые без запроса к базе отвечают, может ли один тенант видеть другого.

## Дерево

Сущность в дереве реализует `IHierarchicalEntity`: свой материализованный путь, то есть идентификаторы от
корня до самой сущности, и свой уровень.

```csharp
public class Tenant : AggregateRoot<Guid>, IHierarchicalEntity
{
    public int[] Path { get; private set; } = [];   // [12, 40, 41]: root 12, then 40, then this one
    public int Level => Path.Length;
}
```

## Правила

`HierarchyRules` сравнивает пути:

| Правило | Истинно, когда цель |
|---|---|
| `target.IsInPlatformScope()` | вне дерева (`null`) или тенант верхнего уровня: то, чем пользователь платформы управляет напрямую |
| `actor.IsInTenantScope(target)` | сам актор или что угодно ниже него в его ветке |
| `actor.IsDirectChild(target)` | на уровень ниже актора, в его ветке |
| `actor.IsDirectParent(target)` | на уровень выше актора, на его пути |
| `actor.IsInDirectScope(target)` | сам актор или его прямой потомок; для данных, которые тенант может видеть у своих детей, но не у внуков |

Каждая политика на стороне сервиса, которая решает, может ли тенант видеть другого, идёт через эти
правила, поэтому дерево значит одно и то же в каждом сервисе.

## Тесты

`Common.Tests` покрывает каждое правило: сам, ребёнок, внук, сосед, предок, другая ветка и уровни
области платформы.
