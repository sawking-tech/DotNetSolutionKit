# Проверки при старте

Неправильно настроенный сервис останавливается при старте и пишет причину в лог, а не падает на первом
запросе, которому нужна недостающая часть.

| Проверка | Падает, когда |
|---|---|
| Валидация настроек при старте | обязательная настройка пуста или вне допустимого диапазона: внутренний API-ключ, пароль дашборда Hangfire, время кэширования CORS preflight |
| Строка подключения | нет `ConnectionStrings:DefaultConnection` |
| Защита схемы | схема сервиса принадлежит другому сервису; см. [хранение данных](../architecture/persistence.md) |
| Валидация DI | нет регистрации или scoped-сервис берётся из корневого контейнера; выполняется при сборке контейнера в каждом окружении |
| Хранилище секретов, с `-I` | хранилище недоступно вне `Local` |

## Неудачный старт заметен

Сервис, который не смог стартовать, логирует исключение как fatal, дублирует его в стандартный поток
ошибок (сбой может случиться до настройки логирования) и завершается с кодом 1. Оркестратор видит
неудачный старт, а не процесс, который штатно завершился.

## Ожидание базы данных

Сервис, запущенный одновременно со своей базой данных, не падает, пока она поднимается: защита схемы
повторяет попытки около 30 секунд, пока PostgreSQL стартует или его порт ещё закрыт. Реплики, которые
стартуют вместе, ждут друг друга: защита держит блокировку на схему, пока создаёт и закрепляет её за
сервисом.
