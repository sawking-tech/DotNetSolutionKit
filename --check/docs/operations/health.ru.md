# Здоровье

| Эндпоинт | Отвечает | Для чего |
|---|---|---|
| `/health` | 200, пока процесс работает; зависимости не проверяет | живость: перезапустить контейнер, когда он перестал отвечать |
| `/ready` | 200, когда проходят все проверки с тегом `ready`, иначе 503 | готовность: направлять трафик, только пока отвечает 200 |

`/health` намеренно ничего не проверяет: при отказе базы данных сервис должен выйти из трафика, а не
перезапускаться по кругу.

Оба отвечают одинаковым телом:

```json
{
  "status": "Healthy",
  "service": "MyCompany.MyProduct.Orders.API",
  "version": "1.2.0",
  "commit": "a1b2c3d",
  "releaseNotes": { "headline": "...", "highlights": [] },
  "timestamp": "2026-10-03T12:00:00Z",
  "checks": { "postgres": "Healthy", "hangfire": "Healthy" }
}
```

`version` и `releaseNotes` берутся из `version.json`, `commit` - из сборки; см.
[ADR-004](../adr/004-product-version-by-hand.md).

## Проверки

Проверки - стандартные health checks ASP.NET Core. У сгенерированного сервиса есть проверка базы данных
(EF Core), а также Hangfire и шины сообщений, если они в сервисе есть.

У шины две проверки. `masstransit-bus` - собственная проверка MassTransit, она отчитывается о receive
endpoints; у сервиса без консьюмеров их нет, поэтому он остаётся здоровым и без брокера. `rabbitmq`
открывает соединение с брокером и держит его между пробами, поэтому `/ready` отвечает 503 уже на первой
пробе после пропажи брокера и снова 200, как только брокер вернулся.

Новая зависимость попадает в `/ready`, если зарегистрировать её проверку с тегом `ready`:

```csharp
builder.Services.AddHealthChecks()
    .AddCheck<PaymentsGatewayHealthCheck>("payments", tags: [HealthConstants.ReadyTag]);
```

Запросы к `/health` и `/ready` логируются на уровне `Verbose`, чтобы пробы раз в несколько секунд не
забивали лог.
